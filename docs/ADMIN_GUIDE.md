# Інструкція для адмінів

Для організаторів з `ADMIN_IDS`. Усі команди вводяться в особистому чаті з ботом. Від не-адміна бот
**мовчки ігнорує** будь-які з них. Інструкція для учасників: [USER_GUIDE.md](USER_GUIDE.md), установка
й сервер: [DEPLOY.md](DEPLOY.md).

## 0. Шпаргалка

### Керування етапами

| Команда | Що робить | Підтвердження |
|---|---|---|
| `/admin` | Панель: етап, реєстрація, кодове слово, лічильники, TODO, кнопки основних дій | ні |
| `/setcode <слово>` | Задає кодове слово (2–64 символи). Діє одразу, старе перестає працювати | ні |
| `/open_reg` | Відкриває реєстрацію (з DRAFT переводить в етап REGISTRATION) | ✅/❌ |
| `/close_reg` | Закриває реєстрацію (етап не змінюється) | ✅/❌ |
| `/start_quest` | Стартує квест, усім зареєстрованим іде «Квест стартував» з кнопкою | ✅/❌ |
| `/start_quest force` | Те саме, але **попри незаповнений контент (TODO)**: лише для тестового прогону | ✅/❌ |
| `/close_in <хв>` | Призначає час закриття (1–600 хв) і розсилає «Квест закриється через N хв». Сам квест **автоматично не закривається** | ✅/❌ |
| `/close_quest` | Закриває квест: усі, хто ще грає, отримують «Квест закрито» + промокод, їхні бали йдуть у рейтинг | ✅/❌ |
| `/publish_results` | Кожному з рейтингу надсилає місце, бал і розбір усіх питань | ✅/❌ |

### Спостереження

| Команда | Що робить |
|---|---|
| `/stats` | Зареєстровано / грають / завершили, розподіл за статусом і курсом, середній бал, 3 найскладніші питання (без адмінів) |
| `/top [N]` | Лідерборд (за замовчуванням 10, максимум 100): місце, ім'я з посиланням на профіль, `@username`, бал, час. Позначка ⏹ = не встиг завершити |
| `/user <id або @user>` | Картка учасника: реєстрація, статус спроби, відповіді з часом, відгук, позначки |
| `/board` | Посилання на живе табло для Zoom (містить секретний токен) |
| `/export` | Три CSV-файли: `participants.csv`, `answers.csv`, `feedback.csv` (відкриваються в Excel) |

### Робота з учасниками

| Команда | Що робить |
|---|---|
| `/exclude <id або @user>` | Прибирає з рейтингу (учасник може грати далі). Підходить для порушників |
| `/include <id або @user>` | Повертає в рейтинг |
| `/broadcast <текст>` | Розсилка всім зареєстрованим. Спершу **попередній перегляд**, потім ✅/❌. Жирний і посилання, зроблені форматуванням Telegram, зберігаються; набрані вручну `<` `&` екранує бот |

### Контент і технічне

| Команда | Що робить |
|---|---|
| `/validate` | Звіт по `content/quest.yaml` з диска: помилки й список TODO |
| `/reload_content` | Перечитує `quest.yaml` без рестарту. Під час гри **заборонено**, якщо файл змінився після старту. Відмовляє при помилках у файлі або якщо зникли питання, які вже є в спробах |
| `/warmup` | Завантажує картинки в Telegram і кешує `file_id` (щоб під час гри вони надсилались миттєво) |
| `/reset_me` | Видаляє **вашу** спробу, щоб пройти квест знову (тест) |
| `/reset_all` | Видаляє **всіх** учасників, спроби, відповіді, відгуки; етап → DRAFT; кодове слово лишається. **Двічі** підтвердити. Не працює під час гри |

> Усі команди з підтвердженням показують повідомлення з кнопками ✅/❌. Повторне натискання зі старого
> повідомлення нічого не ламає: умови перевіряються заново.

## 1. Етапи квесту

```
DRAFT ──/open_reg──▶ REGISTRATION ──/start_quest──▶ RUNNING ──/close_quest──▶ CLOSED ──/publish_results──▶ RESULTS
                                                     (реєстрацію можна відкривати й закривати
                                                      окремо: /open_reg, /close_reg)
```

* Реєстрація працює, лише коли вона **відкрита** і етап REGISTRATION або RUNNING.
* Під час RUNNING реєстрацію можна лишити відкритою: ті, хто зайшов у Zoom пізніше, ще приєднаються (кожному, хто стартує, бот покаже, скільки лишилось до закриття, якщо ви виконали `/close_in`).
* Після `/close_quest` реєстрація закривається автоматично, нові спроби неможливі.
* Старт заблоковано, поки в контенті є незаповнені питання (TODO). У фінальному контенті їх немає.

## 2. Підготовка (до події)

1. **Перевірка конфігурації** на своєму комп'ютері: `python scripts/preflight.py` (перевіряє `.env`, контент, Docker).
2. Запустіть бота на сервері ([DEPLOY.md](DEPLOY.md)).
3. У боті: `/validate` (має бути «Контент готовий до старту»), `/warmup` (картинки), `/board` (відкрийте посилання в браузері).
4. **Генеральний прогін**: із командою пройдіть весь сценарій, потім `/reset_all` (двічі підтвердити).
5. Зберіть `ADMIN_IDS` усіх організаторів у `.env` (інакше їхні команди ігноруються).

## 3. День події

| Коли | Хто | Що |
|---|---|---|
| За день | Адмін | Прогін, `/reset_all`, `/validate`, `/warmup`, перевірка сервера |
| За годину | Адмін | Пост із посиланням на Zoom у каналі |
| На початку слова студпарламенту | Ведучий | Розповідь про квест і призи (слайд з лого партнерів) |
| | Адмін | `/setcode <слово>`, потім `/open_reg` → ✅ |
| | Ведучий | Посилання на бота в чат Zoom, **кодове слово голосом або на слайді** |
| +3–5 хв | Адмін | `/start_quest` → ✅, потім `/close_in 15` → ✅ |
| Під час гри | Ведучий | Показує екран із табло (`/board`) і коментує |
| | Адмін | `/stats` за потреби; стежить за логами (`docker compose logs -f bot`) |
| −2 хв | Адмін | `/broadcast Лишилось 2 хвилини!` → ✅ |
| Кінець | Адмін | `/close_quest` → ✅, потім `/top 5` |
| | Ведучий | Оголошує переможців на табло |
| Після | Адмін | `/publish_results` → ✅, `/export`, зв'язується з переможцями |

## 4. Типові ситуації

| Ситуація | Що робити |
|---|---|
| Учасники пишуть, що слово не підходить | `/admin` → перевірте кодове слово; за потреби `/setcode` (старе одразу перестане діяти). Можливо, закрита реєстрація |
| Хтось запізнився | Реєстрація лишається відкритою під час гри; квест ще не закрито, тож він встигне |
| Бот перезапустився посеред гри | Нічого не робити: після старту бот сам закриває прострочені питання й перепланує таймери, а учасники продовжують |
| Підозра, що хтось грає нечесно | `/user <id>` (відповіді й час), `/exclude <id>`: він лишається в грі, але не в рейтингу |
| Треба нагадати чи повідомити всім | `/broadcast текст` (перегляд → ✅) |
| Помилка в тексті питання під час гри | Не правте файл під час RUNNING: `/reload_content` відмовить, якщо файл змінився. Виправляйте після `/close_quest` (до `/publish_results`), щоб розбір показав правильний текст. Правте лише **текст і пояснення**: уже збережені відповіді не перераховуються, тож зміна `correct` розійдеться з балами |
| Учасник заблокував бота | Автоматично позначається; його спроба доходить до кінця з нулями. Видно в `/user` |
| Помилився й натиснув ✅ не там | Зупинки етапів незворотні (`/close_quest`, `/publish_results`). Перед ✅ уважно читайте текст підтвердження: там видно, скільки людей це зачепить |

## 5. Після події

1. `/export`: збережіть три CSV. Цитати для поста Hillel: `feedback.csv`.
2. `/stats` і `/top 5`: для звіту партнерам і нагородження.
3. Резервна копія БД ([DEPLOY.md](DEPLOY.md), розділ 10).
4. Видаліть персональні дані: `/reset_all`; щоб стерти БД повністю: `docker compose down -v`.
5. Згадайте Englishdom і Telemart у соцмережах (умова партнерів).

## 6. Живе табло

* `/board` дає посилання виду `…/board?token=…`. **Токен секретний**: показуйте екран, а не посилання (особливо в чаті Zoom).
* Показує: стан квесту, лічильники (зареєстровано / грають / завершили), топ-10 з іменами у вигляді «Ім'я П.» і таймер до закриття (після `/close_in`).
* Оновлюється кожні 3 с, темна тема, великий шрифт під показ екрана. Якщо зв'язок пропав, у куті з'явиться «немає зв'язку», а дані лишаться.
* У топі лише ті, хто **завершив** квест (і недопройдені після `/close_quest`), як і в `/top`.
* Табло вимкнене, якщо `BOARD_TOKEN` порожній.

## 7. Що бачить учасник у відповідь на ваші дії

| Ваша дія | Повідомлення учаснику |
|---|---|
| `/start_quest` | «🚀 Квест стартував! Тисни кнопку…» + кнопка «▶️ Почати квест» |
| `/close_in 15` | «⏳ Квест закриється через 15 хв. Встигни завершити!» |
| `/close_quest` | Тим, хто ще грав: «🔒 Квест закрито! Зараховано відповідей: N з M, балів: K» + промокод + призи |
| `/publish_results` | «📊 Результати: твоє місце X з N, бали» + розбір усіх питань (кілька повідомлень) |

Усі тексти для учасників можна правити в `content/quest.yaml → messages` без змін у коді
(`/validate` → `/reload_content`).
